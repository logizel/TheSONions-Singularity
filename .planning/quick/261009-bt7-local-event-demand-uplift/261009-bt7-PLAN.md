<objective>
Anticipate medicine demand from local events (flood, heat wave, cyclone, earthquake, epidemic, festival, other) near a hospital using a deterministic, explainable rulebook. There is no AI or ML. Events live in a new `local_events` table. A pure engine module multiplies the affected forecast days. `buildResults` applies it right after it picks the forecast, so stock-out, waste and moves react on their own. The network admin adds and ends events from an Events sheet. Affected hospitals get a badge, and the insights page and the chatbot quote the reason.

Purpose: Core value is "know before it happens". Today the forecast reacts only after usage has already spiked (outbreak trend). An event 1 km away should move stock before the spike.
Output: The `local_events` table and migration 0005, `lib/engine/events.ts` with tests, wiring in build/load, `/api/events` routes, the Events sheet UI, badges, the insights sentence, and the chat answer.

Locked decisions (user-approved design, /home/anirudh/.claude/plans/can-we-predict-what-cheerful-micali.md):
- EVT-01 (design item 1): a `local_events` table with id, type (flood|heatwave|cyclone|earthquake|epidemic|festival|other), latitude, longitude, radius_km, starts_on, ends_on, severity (1-3), source (manual|feed), note. Migration plus demo rows.
- EVT-02 (item 2): pure rulebook `EVENT_UPLIFT[type][category]` scaled by severity; `eventsAffecting` (haversine within radius, active or upcoming in the 30-day window); `applyEventUplift` (only covered days, overlap takes the max and never stacks, returns reasons[]); tests.
- EVT-03 (item 3): wire into lib/network/build.ts after the fc selection; expose eventReasons per pair plus a hospital-level flag.
- EVT-04 (item 4): admin form to add and end events, a badge on the map and drill-in, and insights text that quotes the reason.
- EVT-05 (item 5): event reasons become quotable chat results, with no calculation in chat.
- Deferred (do NOT build): auto feeds (GDACS/Open-Meteo/NDMA/IMD), learned multipliers, LLM news classifier. `source` = 'feed' is only allowed as a value; nothing writes it.
</objective>

| engine reasons -> chat/UI | Reason strings (including note-free text) are rendered and quoted |
