# 06-01: Live data pipeline, hospital coordinates, routing API

## Tasks

1. **Schema + contract**: `db/schema.ts` hospitals + nullable `latitude`/`longitude` (double precision) and `address` (text). `lib/contracts.ts`: optional fields on `HospitalRow`; `ResultsJSON` v2 (D-03). Run `drizzle-kit generate` only; show the SQL and ask before applying.
2. **Seed**: demo Mangaluru coordinates on `HOSPITALS` in `scripts/seed.ts`, plus an idempotent `scripts/set-demo-coordinates.ts` (UPDATE by id only). Run only with approval.
3. **lib/geo**: `isValidLatLng`, `computeCenter`, `computeBounds` (0/1/many, padded), `haversineM`. Tests.
4. **lib/hospital-locations**: pure `buildHospitalLocations(rows)` drops rows without valid coords. `getHospitalLocations()` reads the DB lazily. Static JSON removed.
5. **lib/routing**: `osrmUrl` (lng,lat), `parseOsrm` (flip to [lat,lng]), `straightLine` fallback, pair cache, injected fetch. Tests without network.
6. **lib/network**: `buildHistory` (60 days, NULL interpolation), `buildResults(input, asOf)` (pure; forecast/outbreak/stockout/waste/moves/priorities), `loadEngineInput()` (lazy DB), `getResults()` (TTL cache → DB → last blob → null). Tests on an inline network.
7. **lib/chat**: `quoteRows(results)` joins names (no arithmetic). Templates read them.
8. **API**: `/api/results` + `/api/chat` → `getResults()`. `/api/hospital-locations` → DB. New `GET /api/route?from&to` (id validation, 404 unknown, 503 DB down, no stack traces).
9. **Scripts/blob**: `scripts/generate-results.ts` → DB pipeline; regenerate `data/results.json` with DB ids (read-only DB access).
10. **Env/docs**: `.env.example` gets SESSION_SECRET, ROUTING_BASE_URL placeholders. Update `docs/hospital-locations-api.md`; add a routing section.
