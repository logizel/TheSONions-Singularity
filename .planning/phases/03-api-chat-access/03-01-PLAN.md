  <action>
    Create middleware.ts with HMAC session verification (using Web Crypto API HMAC-SHA256), role extraction, and hospital scoping. The middleware reads a `session` cookie, verifies its HMAC signature using a `SESSION_SECRET` env var, and extracts `role` + `hospitalId` from the payload. Invalid or missing sessions get 401. Hospital admin gets RW-own/RO-others scoping — write access only to own hospitalId, read access to all. Network admin gets full access.

    Create app/api/chat/route.ts with a POST handler accepting `{question: string}`. The handler calls the chat orchestrator from lib/chat/index.ts and returns `{answer: string}`.

    Create lib/chat/index.ts with a `chat(question: string, resultsJson: ResultsJSON): ChatResponse` function that orchestrates: intent match → template fill → validator check. Returns `{answer: string}` on success or `{answer: REJECTION_SENTENCE}` on any failure.

    Create lib/chat/intents.ts with a `matchIntent(question: string): IntentMatch` function. Implement keyword scoring for one intent: "most-at-risk" (keywords: "risk", "at risk", "most at risk", "danger", "critical"). Return `{intent: string, params: object}` on match or `{intent: "unknown"}` if below confidence threshold.

    Create lib/chat/templates.ts with a `fillTemplate(intent: string, params: object, resultsJson: ResultsJSON): string` function. For the "most-at-risk" intent, extract the hospital with the highest risk score from ResultsJSON and fill a 1-2 sentence template quoting exact numbers (hospital name, risk score, days until stockout). No arithmetic — only string interpolation of values already in ResultsJSON.

    Create lib/chat/validator.ts with a `validateAnswer(answer: string, resultsJson: ResultsJSON): boolean` function. Extract all numeric tokens from the answer (integers, decimals, percentages, dates). Check each token appears verbatim in the ResultsJSON string. Return true only if ALL tokens are found.

    Wire them together: middleware → route → orchestrator → intents → templates → validator → response.
